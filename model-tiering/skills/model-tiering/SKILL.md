# model-tiering —— 按难度定思考档

一条铁律：**先问「多便宜能干成」，不是「多好才能干成」**。
默认从最低档起步，只有出现具体失败信号才升档；绝不因为「这事重要」升档。

## 1. 三档

| 档 | 相对档位 | 派单 | 什么活 |
|---|---|---|---|
| **轻** | 该模型最弱一档 | 不派 | 单步、事实问答、格式转换、单文件小改、闲聊 |
| **中** | 居中一档 | 可派 | 2–5 步、读 1–2 个文件、结果可校验 |
| **高** | 该模型最强一档 | 应派 | 多文件改动、架构、排错、跨系统、不可逆操作 |

（`low/high/max`、`default/high/max`、`low/medium/high`、甚至只有两档）。**具体哪些值以 `config/tiers.json` 的 `models.*.efforts` 为准**，可用 `node scripts/tier.mjs emit` 直接生成各渠道文本。
先用 `list_subagent_models(provider, model)` 看它列出哪几档，再映射成轻/中/高。

**两票否决**（满足任一条，直接定「高」）：
1. 不可逆（删数据、发消息、改系统配置、部署）→ 高 + 用户确认。
2. 要读 ≥3 个文件或预计 >30k tokens → 高（别让主线吞上下文）。

## 2. 三十秒定档（跑规则，不靠感觉）

```powershell
node scripts/tier.mjs classify --text "用户原话" --efforts "low,high,max"
# 定档：mid（reasoning_effort=high）
# 依据：单目标、低风险写操作「改」
```

规则是**本地正则**：几万分之一秒、不调模型、可复现、可改词。判定顺序（先命中先用）：

| 序 | 条件 | 档 |
|---|---|---|
| 1 | 含不可逆动作（完整词表见 `config/tiers.json` 的 `classify.irreversible`） | 高 |
| 2 | 写操作 + 风险词（架构/设计/排查/迁移/重构/并发/性能） | 高 |
| 3 | 写操作 + 涉及代码文件 或 批量（多个/全部/批量） | 高 |
| 4 | 写操作（单目标、低风险） | 中 |
| 5 | 只读但要读代码文件 | 中 |
| 6 | 批量只读 | 中 |
| 7 | 风险词但无写操作 | 中 |
| 8 | 短句/寒暄（≤12 字，无写操作） | 低 |
| 9 | 只读问答 | 低 |
| 10 | 都没命中 | **中（上判，宁可贵一点也别降质）** |

**为什么这样不会拖慢产出**：分类在派活之前跑，几十毫秒，纯本地，不占对话上下文；
判错也只会多花一点或多想一点，不会卡住任务。

**为什么这样不会降质**：只有「明确的只读问答/寒暄」才给低档；一切模糊、写操作、代码相关、风险词都向上判。
用户说「认真点 / 别省钱」时直接跳到高档，规则不参与。

**定完档要在回答里说出来**（这是唯一给用户的可见反馈，右下角那格改不了）：

```
▸中
```

一行就够，放回答最前面。所有渠道都写，人设会话也不例外。

关键词表在 `config/tiers.json` 的 `classify` 里，觉得哪类判错了就改词，不用改代码。

## 3. 怎么真正改到思考档（重要，别吹）

**派子代理时带 `reasoning_effort`，真的生效，且不需要任何白名单**（已实测）：
provider/model 与当前会话相同、只改 `reasoning_effort` 时，DSH 直接接受。
换**模型**才需要白名单（见 §6）——但本 skill 不换模型。

⚠️ **档位名必须来自模型本身**，写错会被拒（报错是 `does not support reasoning effort`）。
每次换模型、或不确定时，先查再映射：

```powershell
# 1. 看这个模型支持哪几档（工具输出，按弱→强抄下来）
list_subagent_models(provider, model)
# 2. 映射成轻/中/高
node scripts/tier.mjs map --efforts "low,high,max"
# 3. 取某一档
node scripts/tier.mjs route high --efforts "low,high,max"
```

映射规则固定为相对位置：**轻=最弱、高=最强、中=居中**（两档模型时中=高）。
已知模型的档位缓存在 `config/tiers.json` 的 `models` 里：`node scripts/tier.mjs route mid --model provider/model`（档位名 + 模型一起给）。

⚠️ **界面文字 ≠ API id**：界面可能把 `low` 显示成「默认」、把 `max` 显示成「最高」。
派单和切换一律传 API id，不要传界面上的中文。

- **轻**：自己干，别派。子代理启动要带一整份系统提示，一句话的活派出去反而更贵。
- **中/高**：派出去并带对应 `reasoning_effort`，主线只收结论——这是省钱的主路径。
- **主会话自己**：GUI 里没有改本会话等级的入口（此前尝试的第三方插件未能加载，已撤除）。主会话的等级由 profile 默认值决定；
  本 skill 对主会话的作用是「少干、早派」，不是「调低自己的思考」。

不要对用户宣称「我已经把自己的思考等级调低了」——那条改不了。可以说「这个活我按低档派出去跑」。

## 4. 升级护栏

只有出现**具体信号**才升一档，并在回复里写一行 `↑高 因为 <信号>`：

| 信号 | 动作 |
|---|---|
| 子代理连续 2 次不达验收 | 升一档重派（把失败原因写进 prompt） |
| 测试/编译失败且原因不明 | 升一档 |
| 出现「架构 / 设计 / 排查 / 为什么 / 最优 / 重构」 | 可升到「高」，但受每日上限约束 |
| 用户说「认真点 / 别省钱」 | 直接高，并说明这次不走省钱策略 |

禁止：一次升两档；因为「重要」升级；同一个失败原样重派第三次。

## 5. 成本纪律（比调等级更管用）

- 定位靠 `grep`/`glob`，只 `read` 命中片段，不整文件反复读。
- 子代理 prompt 只给必要上下文，不整段贴聊天记录。
- 长产物落文件，不在对话里刷全文。
- 说过的不复述；结尾不写三段总结。
- 简单问题上别开多轮自检——「轻」档就是一次成型。

## 6. 什么时候才需要开白名单

只在**要换模型**的时候（比如想让轻活跑更便宜的另一款模型）。开法：

1. 侧栏 **插件** → 官方分组 → **子智能体**
2. **模型选择** → 开权限 → 勾上目标模型 → **保存**

验证：`list_subagent_models` 能列出多条路由即为生效（可能需要新开会话）。

**只改思考档不需要白名单**；没开白名单时本 skill 照样能用，只是所有档位跑同一个模型的不同思考强度。

## 7. 记账

```powershell
node scripts/tier.mjs log --tier high --reason "排查偶发卡死" --tokens 4200
node scripts/tier.mjs stats --days 7
node scripts/tier.mjs budget
```

「高」档每日上限（`config/tiers.json` 的 `guard.maxHighPerDay`，默认 6）由 `budget` 计数提醒，**脚本不强制拦截**——超了要自己停下问用户，别默默烧。

## 8. 反模式

- ❌ 所有任务都按「高」——这正是成本失控的来源。
- ❌ 把需求丢给子代理，自己不看结果就转述。
- ❌ 同一个活派 3 个子代理「投票」。
- ❌ 一边说省成本，一边每轮都在多轮自检。

判定细则与实例见 `references/rubric.md`。
